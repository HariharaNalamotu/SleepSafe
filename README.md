# SleepSafe 


**Wearable audio analysis for better sleep awareness at home.** SleepSafe connects a Bluetooth headset to a Raspberry Pi to record nighttime audio, identify breathing and sound patterns, and present the results through a web dashboard. > **Main code:** The current implementation is in the [`hari` branch](https://github.com/HariharaNalamotu/SleepSafe/tree/hari). Switch to that branch to access the main project code. ## Overview SleepSafe helps people understand nighttime breathing and sounds through timestamped events and readable session reports. Our initial focus is sleep wellness and personal awareness, with a longer-term ambition to support clinician-directed home assessments. SleepSafe is a research prototype. Its experimental breathing-event estimates are not clinically validated diagnostic results, and it does not replace a clinical sleep study. ## How It Works 1. **Connect:** Pair a Bluetooth headset with the Raspberry Pi. 2. **Record:** Press **Start recording** on the web dashboard. 3. **Upload:** The Pi captures audio and uploads it in 10-second chunks. 4. **Process:** Press **Stop recording** to trigger the Databricks analysis workflow. 5. **Review:** Explore the session summary, event timeline, and plain-language report. The Pi uses outbound HTTPS to receive recording commands and publish its status, so it does not require an inbound internet connection. ## Features - Remote Start/Stop recording controls. - Continuous audio uploads with local spooling. - Experimental estimates of breathing events per hour and sleep time. - Snoring analysis and timestamped breathing events. - Interactive event timeline with expandable details. - Plain-language reports generated from structured findings. - A separate Databricks companion app for classification and questions about session data. ## Technology Stack | Component | Technologies | |---|---| | Wearable audio input | Bluetooth headset microphone | | Capture device | Raspberry Pi running Ubuntu | | Recording pipeline | Python, PipeWire, FFmpeg | | Audio format | 16 kHz mono | | Audio model | Frozen PANNs CNN14 encoder and bidirectional GRU | | Storage | Databricks Unity Catalog Volumes and Delta tables | | Processing | Databricks serverless CPU workflows | | Report generation | `databricks-gpt-oss-120b` | | Dashboard | Next.js, React, TypeScript | | Web deployment | Vercel | ## Audio Analysis The audio model uses technician-scored PSG-Audio recordings from **79 subjects**, split by subject into: - **59** training subjects. - **10** validation subjects. - **10** test subjects. A frozen PANNs CNN14 encoder extracts per-second acoustic features. A compact bidirectional GRU learns apnea, hypopnea, snoring, and sleep/wake patterns. Post-processing converts predictions into timestamped events. AudioSet evidence gates help reduce speech being mistaken for sleep or snoring. The language model explains the structured findings in a readable report. ## Prototype Results | Evaluation | Result | |---|---| | Apnea + hypopnea event F1 on tracheal audio | **0.835** | | Apnea + hypopnea event F1 on ambient audio | **0.801** | | Snore F1 before and after AudioSet gates | **0.42 → 0.47** | | Reference recording through the Pi pipeline | **8 minutes, 48 chunks, completed report** | | Consumer Bluetooth headset | Pairing and live microphone input verified | The model scores are offline results from a held-out hospital dataset. They do not establish clinical accuracy or consumer-headset performance. Full overnight headset validation remains future work. ## Getting the Code Clone the main implementation directly: ```bash git clone --branch hari https://github.com/HariharaNalamotu/SleepSafe.git cd SleepSafe ``` If you already have the repository: ```bash git fetch origin git switch hari git pull --ff-only origin hari ``` Run the recording agent on the Raspberry Pi connected to the headset. The web dashboard and Databricks workflow run separately. Follow the component-specific configuration and setup instructions in the `hari` branch. ## Data Protection Databricks credentials remain server-side. The prototype also implements data masking in Databricks following feedback from Tyler and Patrick at Xorbix. Masking is one protective layer and does not establish complete security or regulatory compliance. Do not commit credentials, private recordings, or sensitive session data to the repository. ## Roadmap - Compare paired headset and reference recordings. - Evaluate noise suppression, fit, false positives, and reduced-breathing events. - Improve signal-quality feedback. - Test the experience with intended users and sleep-care professionals. - Validate hardware costs, cloud costs, and the proposed reusable-kit and reporting-service model. - Explore custom electronics to make the wearable smaller and more comfortable, with a long-term goal of a fingertip-sized form factor. - Pursue clinical partnerships and studies toward appropriately authorized clinician-directed use. Diagnostic use, regulatory authorization, and insurance reimbursement are future milestones. ## Acknowledgments Thank you to **Tyler and Patrick at Xorbix** for feedback that led to implemented data masking, and **Carter at Strato VC** for helping shape the initial wellness-focused product strategy.
